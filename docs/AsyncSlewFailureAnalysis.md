# `SlewToCoordinatesAsync` — Post-Return Failure Mode Catalogue (SkyWatcher)

**2026-08-01 13:05**

The method returns to the caller once `ExecuteSlewAsync` completes its **Setup Phase** and fires off the background `_movementTask`. Everything after that point runs on a `ThreadPool` thread inside `ExecuteMovementAndCompletionAsync`. The failures below are grouped by your three categories.

---

## Architecture recap (call chain after return)
```
SlewToCoordinatesAsync  ← returns here
  └─ SlewRaDecAsync → SlewAsync → ExecuteSlewAsync  [returns SlewResult]
       └─ _movementTask = Task.Run(ExecuteMovementAndCompletionAsync)
              ├─ MovementPhaseAsync
              │     └─ SlewOperation.ExecuteMovementAsync
              │           └─ SkyGoTo  (Mount.Motion.cs:400)
              │                 ├─ SkyTasks(StopAxes)
              │                 ├─ SkyAxisGoToTarget  × 2  [first slew]
              │                 ├─ SkyIsAxisFullStop poll loop (240 s timer)
              │                 └─ SkyPrecisionGoto
              │                       └─ SkyAxisGoToTarget + SkyIsAxisFullStop poll loop × 5
              ├─ CompleteAsync  (SlewOperation.CompleteAsync)
              │     └─ CompleteRaDecSlewAsync (AltAz only), MarkComplete, ApplyTracking
              ├─ HandleCancellationAsync  (on OperationCanceledException)
              └─ HandleErrorAsync         (on any other Exception)
                   └─ Mount._mountError = new Exception(...)  ← silently stored
```

## Category 1 — Runtime / .NET / OS Failures

These propagate as unhandled exceptions inside the background `Task.Run`. They are **caught by `HandleErrorAsync`**, which stores them in `Mount._mountError` and calls `ForceStopAxesAsync`. They are **never re-thrown to the caller**.

| # | Failure | Where it occurs | How it manifests |
|---|---------|----------------|-----------------|
| 1.1 | `OperationCanceledException` from `CancellationToken` | `SkyGoTo` — `token.ThrowIfCancellationRequested()` / `token.WaitHandle.WaitOne()` | Caught by `HandleCancellationAsync`. Mount stops, `_slewState = SlewNone`, tracking restored. **Caller never informed.** |
| 1.2 | `ThreadAbortException` / `TaskCanceledException` from `Task.Run` outer CTS | `ExecuteMovementAndCompletionAsync` outer `Task.Run` cancel | Same as 1.1 — caught as `OperationCanceledException`. |
| 1.3 | `ObjectDisposedException` | If `SkyQueue` or `_currentOperationCts` is disposed mid-slew (e.g. disconnect) | Falls through to `HandleErrorAsync`, stored in `_mountError`. |
| 1.4 | `OutOfMemoryException` / `StackOverflowException` | Unlikely but possible during large iteration in precision loop | `StackOverflowException` is fatal to the process; `OutOfMemoryException` is caught by `HandleErrorAsync`. |
| 1.5 | `AggregateException` unwrap from `Task.Run` | If the inner task throws multiple exceptions | The first inner exception reaches `HandleErrorAsync`. |

## Category 2 — Algorithmic / Logic Failures

These are **generated within the slew execution logic itself**, mostly in `SkyGoTo` and `SkyPrecisionGoto`.

| # | Failure | Where it occurs | Effect |
|---|---------|----------------|--------|
| 2.1 | **Setup timeout** (950 ms): `OperationCanceledException` when `setupTimeoutCts` fires | `ExecuteSlewAsync` — before return | Returns `SlewResult.Failed("Setup phase exceeded 1 second timeout")` **before** the method returns. The caller *does* get `GetAwaiter().GetResult()` — but the result is discarded in `SlewToCoordinatesAsync`. **Silent failure.** |
| 2.2 | **Mount not running**: `SlewResult.Failed("Mount not running")` | `SetupPhaseAsync` line 322 | Same — result discarded. `IsSlewing` never set to `true`. |
| 2.3 | **Previous motion stop failure**: `SlewResult.Failed("Could not stop previous motion")` | `SetupPhaseAsync` line 334 | Same — result discarded. No movement starts. |
| 2.4 | **`TimeoutException`** from `WaitUpdateMountPosition(5000)` | `SkyPrecisionGoto` line 621 | Thrown inside background task. Caught by `HandleErrorAsync`. `_mountError` set. Mount stopped. **Caller not informed.** |
| 2.5 | **`NullReferenceException`** from `GetRawDegrees()` returning `null` | `SkyGoTo` RA pre-correction block and `SkyPrecisionGoto` line 641 | `SkyGoTo`: guarded by null-check, correction silently skipped. `SkyPrecisionGoto`: `break` out of precision loop — slew completes at first-slew accuracy only. |

## Category 3 — Hardware / Mount Communication Failures

These occur when the SkyWatcher command queue cannot complete a command, or the serial/UDP transport fails.

| # | Failure | Where it occurs | Effect |
|---|---------|----------------|--------|
| 3.1 | **`SkyAxisGoToTarget` command not acknowledged / queue not running** | `SkyGoTo` lines 455–456 (first slew) and precision loop lines 679, 689 | Commands are fire-and-forget (`_ = new SkyAxisGoToTarget(...)`). **No result is checked.** If the queue is dead, commands are silently dropped. The axis never moves; poll loop runs until 240-second `timer` expires. |
| 3.2 | **Axis status poll returns `!x.Successful`** | `SkyGoTo` lines 475–478, 500–503 | `abortReason` set, poll loop `break`s. `firstSlewCompleted = false`. Precision loop skipped. `SkyGoTo` returns `success = 0` **regardless**. Caller gets no indication of abort. |
| 3.3 | **`InvalidOperationException` from `SkyIsAxisFullStop`** (e.g. queue shut down mid-slew) | `SkyGoTo` lines 482–486, 507–510 (first slew); precision loop lines 709, 721 | `abortReason` set in first slew → loop exits. In precision loop: inner `break`, continues next iteration. Both degrade silently. |
| 3.4 | **Serial/USB disconnect during slew** | Deep inside `SkyQueue.GetCommandResult(...)` | Surfaces as `IOException`, `TimeoutException`, or `InvalidOperationException` depending on where in the transport layer. If unhandled by the queue, propagates to `SkyGoTo` poll, gets stored as `abortReason` or caught by outer `HandleErrorAsync`. `_mountError` set. |
| 3.5 | **Mount hardware fault (motor overload, overcurrent, low voltage)** | SkyWatcher firmware returns error response byte | Response parsed in the SkyWatcher command layer. If `x.Successful = false`, same as 3.2. Low-voltage specifically sets `_lowVoltageEventState` flag via the monitoring timer — but this does **not** cancel the in-progress slew. |
| 3.6 | **`SkyTasks(StopAxes)` ignored because `IsMountRunning = false`** | `Mount.Tasks.cs` line 284 | `StopAxes` is silently no-op'd. Axes may not be stopped before the GoTo commands are issued. |
| 3.7 | **`ForceStopAxesAsync` failure** (in error/cancel handlers) | `SlewController.ForceStopAxesAsync` | Exception caught internally and logged as Error. Axes physically may not stop. No escalation. |
| 3.8 | **`WaitUpdateMountPosition(5000)` timeout** in precision loop | `SkyPrecisionGoto` line 608 | Throws `TimeoutException` — this IS the one hardware-related exception that **escapes** `SkyGoTo` and reaches `HandleErrorAsync`. Sets `_mountError`. Mount stopped. |

## Key Architectural Gap — Caller Blindness

The most important observation cutting across all three categories:

> **`SlewToCoordinatesAsync` discards the `SlewResult` returned by `ExecuteSlewAsync` (line 1533 in Telescope.cs), and the entire background `_movementTask` is unobserved after the method returns.**

Concretely:
- `SlewResult.Failed(...)` from **2.1, 2.2, 2.3** → result is `GetAwaiter().GetResult()`'d and then discarded.
- Any exception from the background movement (categories 1, 2.4–2.9, 3.2–3.8) → caught by `HandleErrorAsync`, stored in `Mount._mountError`, **never surfaced to the Alpaca client via an exception**.
- `SkyGoTo` always returns `success = 0` regardless of whether `firstSlewCompleted` is `false` due to hardware abort (3.1–3.3).

The caller's only way to detect post-return failure is:
1. Polling `Slewing` property (which becomes `false` when `CleanupOperation` runs — even on error).
2. Reading `Mount._mountError` — but that field is `internal` and not exposed through the ASCOM Alpaca interface.
3. Noticing the mount is not at the commanded target when they next read `RightAscension`/`Declination`.
